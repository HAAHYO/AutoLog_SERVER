# AutoLog — 제품 스펙 (초안)

> **상태: 초안.** README의 한 줄 설명("실시간 환율 스트리밍 및 복식부기 원장 기반 지정가 자동 환전 엔진 서비스")을 바탕으로 쓴 문서입니다. "가정"으로 표시한 항목은 확정된 사항이 아닙니다. 결정이 나면 이 문서를 고치고, 아래 "미결정 질문"에서 해당 항목을 지웁니다.

## 목적

사용자가 **원하는 환율(지정가)**을 정해 두면, 실시간 환율이 그 조건에 도달했을 때 **자동으로 환전**해 주는 서비스입니다. 모든 돈의 이동은 **복식부기 원장**에 기록하여, 잔액을 언제든 원장으로부터 재계산하고 검증할 수 있게 합니다.

## 핵심 구성 요소

| 구성 요소 | 설명 |
|-----------|------|
| 실시간 환율 스트리밍 | 외부 환율 공급자로부터 통화쌍 환율을 계속 수신합니다. 클라이언트에도 실시간으로 전달합니다 (가정: SSE 또는 WebSocket). |
| 지갑 / 잔액 | 사용자별, 통화별 잔액입니다. 잔액의 근거는 원장입니다. |
| 지정가 주문 | "USD 100을 1,350원 이하일 때 매수"처럼 통화쌍, 방향, 금액, 지정가를 담은 주문입니다. |
| 체결 엔진 | 새 환율이 들어올 때마다 대기 중인 주문을 평가해 조건에 맞으면 체결합니다. 체결은 정확히 한 번만 일어나야 합니다. |
| 복식부기 원장 | 입금, 환전, 수수료 같은 모든 사건을 차변과 대변이 균형을 이루는 분개로 기록합니다. append-only입니다. |

## 핵심 시나리오 (가정)

1. 사용자가 가입하고 로그인합니다. 인증 방식은 미결정입니다.
2. 사용자가 KRW 잔액을 충전합니다. 실제 결제를 할지, 모의 충전으로 할지는 미결정입니다.
3. 사용자가 실시간 USD/KRW 환율을 봅니다.
4. 사용자가 "1,350원 이하가 되면 USD 100 매수" 지정가 주문을 등록합니다.
5. 환율이 1,350원 이하로 내려오면 체결 엔진이 주문을 체결합니다. KRW는 차감되고 USD가 들어오며, 원장에 분개가 기록됩니다.
6. 사용자는 주문 내역, 체결 내역, 잔액, 원장 내역을 조회합니다.
7. 사용자는 체결 전의 주문을 취소할 수 있습니다.

## 업무 규칙 (확정된 것만)

- 금액과 환율은 소수 오차 없이 처리합니다(`BigDecimal`).
- 원장은 수정하거나 삭제하지 않습니다. 정정은 역분개로 합니다.
- 한 분개 안에서 통화별 차변 합계와 대변 합계는 같아야 합니다.
- 하나의 주문은 최대 한 번만 체결됩니다.

## 미결정 질문

구현하다가 이 질문에 걸리면, 혼자 정하지 말고 사용자에게 물어봅니다. 임시로 정하고 진행해야 한다면 보수적인 쪽을 택하고, PR 본문에 그 가정을 적습니다.

| # | 질문 | 영향 범위 |
|---|------|-----------|
| 1 | 환율 공급자는 어디인가? (실제 API? 모의 생성기?) 수신 방식은? (폴링 / WebSocket) | rate 도메인, 체결 엔진 |
| 2 | 지원 통화쌍은 무엇인가? (KRW↔USD만? 다통화?) | CurrencyCode, 원장 계정 |
| 3 | 충전과 출금은 실제 결제인가, 모의인가? | 외부 청산 계정, 보안 |
| 4 | 인증 방식은? (이메일/비밀번호 + JWT? 소셜 로그인?) | user 도메인, Spring Security 도입 |
| 5 | 지정가 도달 시점에 잔액이 부족하면 거절할까, 대기시킬까? | 주문 상태 머신 |
| 6 | 주문에 만료(유효기간)가 있는가? | EXPIRED 상태, 스케줄러 |
| 7 | 부분 체결이 있는가? (전량 체결만?) | 주문 모델, 원장 |
| 8 | 수수료(스프레드)가 있는가? 있다면 어떻게 계산하는가? | 체결 금액, 수수료 수익 계정 |
| 9 | 주문을 등록할 때 잔액을 미리 묶어 둘까(hold), 체결할 때 차감할까? | 잔액 모델, 동시성 |
| 10 | 체결 기준 환율은 무엇인가? (매수/매도 호가? 중간값?) | 체결 엔진 |
| 11 | 클라이언트는 무엇인가? (웹? 앱?) 실시간 전달 방식은? | 스트리밍 API |
